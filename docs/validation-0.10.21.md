# 0.10.21 검증 기록 — 2026-11-06

## 변경

- 0.35초 여유에서 끊김이 많다는 사용자 피드백에 따라 기존 두 모드를 **2초 / 1.5초 / 1초** 단일 선택으로 교체했다. 기본 및 이전 `stable`/`lowLatency`/잘못된 값은 2초로 정규화한다. 새 값은 문자열/숫자로 저장돼도 같은 값으로 읽는다. 기존의 자동 따라잡기 꺼짐은 유지한다.
- 선택한 여유는 고정이다. 버퍼링에 따른 확대와 안정 재생 시 자동 축소를 제거했다. 0.35초를 사용하는 실행 경로가 없다.
- 자동 보정의 위치 이동을 제거했다. 내려받은 최신 지점과 선택 여유의 차이에 따라 1.15→1.08→1.03→1배속으로 조절한다. 실제 위치 이동은 **지금 따라잡기**의 명시적 `force` 경로에서만 허용하며 버퍼·탐색 가능 범위와 앞으로만 이동하는 조건을 유지한다. 30초 중단은 다시 추가하지 않았다.
- 플레이어와 팝업에 같은 세 칸 라디오 스위치를 표시한다. 초록색 바는 0/100/200%로 이동하며 저장·외부 변경 동기화·키보드 조작·해제 시 비활성화를 유지한다.
- 옵션 설명은 기본 `title` 툴팁 대신 CSS hover/focus 툴팁이다. 타이머·표시 지연·진입 애니메이션 없이 즉시 표시한다. 설명은 공유 메타데이터에서 생성하며 모든 옵션에 끊김 가능성을 안내한다. 마우스가 다른 옵션에 있을 때 키보드 포커스 설명과 겹치지 않도록 마우스 설명을 우선한다.

## 검증

- 수정 전 소스를 새 모드 모형에 넣었을 때 15개 중 12개 실패했다. 자동 위치 이동, 고정 선택 여유, 모드 전환의 기존 동작을 재현했으며 `artifacts/regression-0.10.21-before.json`에 보존했다.
- 관련 모드·설정·광고 회귀 모형 10개 페이지의 검사 144개 통과, 페이지 예외 없음. 반복 버퍼링·장시간 재생에도 선택한 여유가 고정이고 자동 `currentTime` 쓰기가 없음을 확인했다.
- 실제 포인터/키 입력 검사 30개 통과: 세 여유 각각에서 자동 이동·타임바·되감기·배속 복귀는 배속으로만 보정했다. 소스가 `currentTime`을 쓴 횟수는 명시적으로 누른 지금 따라잡기 3회와 정확히 일치했다. 결과: `artifacts/catch-up-seek-0.10.21-after.json`.
- 플레이어/팝업 양쪽에서 세 칸의 단일 선택·저장·슬라이드 중간/종료 위치·키보드 조작을 검사했다. 마우스 진입 직후 지연이나 polling 없이 첫 스타일 조회에서 설명이 보였고, 키보드 설명과 hover 우선순위도 확인했다. 화면 PNG를 확인했다. 증거: `artifacts/catch-switch-0.10.21.json` 및 같은 이름의 player/popup PNG.
