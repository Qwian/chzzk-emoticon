# 0.10.14 검증 기록 — 2026-11-02

## 원인 경로와 변경

- 치지직 공개 플레이어 코드에서 `#midAdPlayerWrapper` 안에 본방송용 `video#midPlayer`와 `#midAdVideoContainer`가 함께 생성되는 구조를 확인했다. 기존 코드는 원래 `.webplayer-internal-video`가 이 wrapper 밖에 있으면 wrapper 전체를 축소했다. 이 구조를 모사한 검사에서 본방송까지 함께 작아지는 실패를 재현했다. 사용자의 실제 웨일 DOM을 직접 확인한 결과는 아니다.
- 광고 영상 컨테이너에만 우측 상단 26% 축소를 적용한다. 공유 wrapper와 본방송 경로는 전체 크기로 복원한다. 재생 중인 `#midPlayer`가 있으면 원래 본방송이 멈춘 상태에서도 배치를 적용한다. 보조 영상이 준비되지 않았으면 재생 중인 원래 본방송을 사용한다.
- 본방송이 모두 멈추거나 광고 종료·설정 해제·채널 이동이 발생하면 확장의 배치 클래스를 제거한다. 광고 음소거·배속·스킵, SDK 다시보기 처리는 유지한다.

## 검증

- 새 공유 컨테이너 검사 11개 중 기존 코드에서 6개 실패, 수정 후 11개 통과. 공유 wrapper와 별도 본방송의 위치·너비·높이가 플레이어 전체와 일치하고 광고만 오른쪽 위 26%로 표시되는지 실제 브라우저 계산 크기로 확인했다.
- 기존 광고 배치·준비 단계·초기화·제거된 DOM·소리·배속·스킵·사이트 도구와 합쳐 브라우저 모형 114개 통과, 페이지 오류 없음.
- 격리 Edge 프로필에서 v0.10.14 확장 로드 검사 2개 통과. 정상 초기화와 document_start helper 누락 후 document_idle 복구에서 manifest 오류·확장 예외 없음.
- 루트 JavaScript 전체 문법, manifest 파싱, Node 검사 29개 통과.
- 사용자 웨일의 실제 생방송 광고와 로그인 채팅 입력·전송은 수행하지 않았다. 모형 검사를 실제 생방송 확인으로 간주하지 않는다. 게임 조작 없음.
