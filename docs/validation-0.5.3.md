# 0.5.3 검증 기록 — 2026-10-29

## 확인한 실패 경로

사용자가 0.5.1의 보정을 추가한 뒤에도 360p이며 치즈 플래터에서는 된다고 알려왔다. 기존 보정은 JSON.parse와 Response.json만 가로챘으나, 현재 치지직 [페이지 코드](https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/index-DWn2Eab5.js)의 live-detail-meta 요청은 [공개 vendor 코드](https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/vendor-CcTi-6A6.js)의 터널을 사용한다. 이 코드는 AES-GCM 복호화 결과를 자체 바이트 파서 `_0x124f4f`에 넘긴다. 전역 JSON.parse 감시는 이 경로에 적용되지 않는다.

공개 vendor 파일에서 파서와 문자표만 추출해 로컬로 실행했다. 합성 메타데이터를 실제 브라우저 AES-GCM으로 암호화·복호화한 후 이 파서에 전달하자 0.5.2에서는 `dab` 보정과 강제 화질 조건 해제가 실패했고, 0.5.3에서는 통과했다. 실제 계정 응답이나 재생 토큰은 사용하거나 저장하지 않았다.

또한 [치즈 플래터의 화질 메뉴 처리](https://github.com/lirpa62/Chzzk-Platter/blob/main/src/audioMixer.js#L5834)는 원본 메뉴 항목을 잠시 분리해 클릭한 뒤 복원한다. 연결된 항목을 그대로 클릭하던 우리 코드와 다르다. 이 이벤트 경로를 모사한 로컬 fixture에서도 기존 코드는 변경 핸들러 호출에 실패했고 새 코드는 통과했다. 이 fixture의 페이지 차단 핸들러는 모사한 것이며 실제 치지직에서 직접 입력한 검증과 구분한다.

## 최종 변경

- 효과 없던 전역 JSON.parse/Response.json 수정을 제거했다.
- 현재 터널의 `gfp-tunnel-response-v1` 추가 인증 데이터 표식과 AES-GCM 알고리즘에 한정해 복호화 결과를 처리한다. 확인된 라이브·다시보기 구조의 유일한 `dab: true` 토큰만 변경하며 다른 바이트·큰 정수·BOM·영상 주소·P2P·접근 조건을 보존한다. 일반 암호화 응답과 오류 응답은 그대로 통과한다.
- 기본 화질 항목의 원본 이벤트를 호출한 뒤 다음 프레임에 원본 메뉴를 복원한다.
- 확장 팝업에서 최상위 프레임의 응답·보정 횟수와 영상의 실제 videoHeight를 보여준다. 카운터와 상태만 메모리에서 주고받는다.

## 검증

- 루트 JavaScript 문법 검사, manifest JSON 파싱, git diff --check.
- Node 8개 테스트: 기존 core 4개, 변경한 터널 응답 보정 4개. 설정·순서·라이브/VOD·인증 표식·응답 구조·복호화 오류·바이너리·큰 정수·BOM·모호하거나 이스케이프된 키를 검사했다.
- 브라우저: 자체 파서와 실제 AES-GCM 경로 7개, 저장소 내 독립 파서 소비 경로 7개, 화질 메뉴 3개, 기존 광고/화질 6개, 배속/프레임 9개, 팝업 진단 표시와 최상위 프레임 지정 2개 항목을 확인했다.
- 실제 치지직 채팅에는 입력하거나 전송하지 않았다.

## 실제 환경의 한계

등록된 프로젝트 폴더의 변경은 완료했지만 브라우저 확장 관리 화면의 도구 접근 제한으로 사용자 확장을 직접 다시 로드하지 못했다. 사용자 환경에서 AdGuard를 켠 상태의 메뉴 복구와 실제 고화질 디코딩을 아직 확인하지 못했다. 이 릴리스의 로컬 파서 회귀 검사 통과를 사용자의 1080p 재생 확인으로 보고하지 않는다. 업데이트 후 확장 다시 로드와 방송 탭 새로고침이 필요하다.
