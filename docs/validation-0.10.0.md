# 0.10.0 검증 기록 — 2026-11-01

## 확인한 구조와 수정

공개 치지직 다시보기에서 채팅은 `#vod-aside`이고 라이브와 달리 section 아래 플레이어 div와 영상 div가 중첩되어 있었다. 플레이어 ID도 `#player_layout`이었다. 해당 컨테이너를 지원하고 일반 화면의 폭 조절, 넓은 화면의 이동·크기·투명도, 내부 높이와 닫기 정리를 보완했다. 채팅 목록과 문서는 재생성하지 않는다.

공개 치지직의 현재 스크립트에서 `window.__workingChat` 작성 상태와 DOM이 별도로 관리되는 것을 확인했다. 기존 DOM 제한에 네이티브 작성 상태를 포함하고 Enter keydown/keypress와 전송 버튼에서도 초과 메시지를 차단한다. 문자열 매핑은 선택 영역을 교체한 전체 결과를 계산해 앞뒤 문장과 합쳐지는 코드도 센다. 한 물리 키가 keyup 전에 repeat 없이 다시 들어오는 경우도 한 번만 처리한다. 삭제 입력은 IME 감시의 안전 지점을 갱신해 삭제한 내용을 복원하지 않으면서 늦은 조합 입력을 계속 제거한다. 전송 성공을 추측해 사용자 문장을 강제로 지우지 않는다.

배속은 로컬 영상과 안내에 즉시 적용한다. 백그라운드의 전역 대기열과 프레임 응답 대기를 제거하고, 이전 자기 명령의 늦은 적용·응답은 최신 조절을 되돌리지 못하게 한다. 영상 없이도 배속을 지정하며 나중에 생긴 영상에 적용한다. 안내는 브라우저 뷰포트 좌상단 16px이고 iframe에서는 상위 프레임으로 전달한다. 브라우저 밖 OS 바탕화면에는 표시하지 못한다. 페이지 자체의 메인 스레드 정지까지 해결했다고 주장하지 않는다.

유튜브는 원래 채팅 iframe 안에서도 최소 폭을 해제하고 메시지 줄바꿈을 적용한다. 별도 권한 없이 기존 youtubeWide 설정을 따른다.

라이브 광고 축소 시 본방의 source wrapper뿐 아니라 별도로 줄어든 상위 영상 컨테이너도 전체 크기로 맞춘다. 본방이 정지하면 광고 축소를 해제한다. 공개 다시보기에서는 라이브 ID 광고 컨테이너 대신 `.webplayer-internal-core-ad-ui`와 `video[data-role=videoEl]`을 사용하는 것도 확인했다. SDK가 광고 상태이고 실제 소스·재생 데이터가 있는 광고만 감지하며, 가려진 영상 경로를 표시해 기본 스킵 컨트롤을 유지한다. 준비용 빈 영상과 autoplay probe는 제외한다. 광고 종료 후 표시·음소거·배속을 복구한다. 본편 다시보기에는 자동 따라잡기를 적용하지 않는다.

## 수정 전 비교

HEAD 0.9.5 소스를 artifacts/baseline-0.10.0에 보존하고 같은 fixture로 비교했다.

- 입력 검사: repeat 없는 중복 keydown, 삭제 후 이전 내용 복원, 네이티브 상태의 11번째 입력·전송 차단이 기존 코드에서 실패했다.
- 문자열 검사: 앞 문장과 합쳐진 11번째 코드와 네이티브 상태를 포함한 제한 2개가 실패했다.
- 다시보기 채팅: 도구 설치, 일반 폭 조절 손잡이, 넓은 화면 자유 배치가 실패했다.
- 광고 배치: 본방 상위 크기, 본방 정지 시 광고 복귀, SDK 광고 표시·스킵·음소거 5개가 실패했다.
- 백그라운드: 적용 응답을 끝내지 않는 프레임을 모사하면 기존 12개 검사는 통과했으나 추가한 명령 대기열 회귀 검사는 실패했다.

이는 로컬 재현 조건이며 사용자의 실제 환경에서 모든 원인이 같다고 확정한 결과는 아니다.
