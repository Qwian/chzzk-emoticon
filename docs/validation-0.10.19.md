# 0.10.19 검증 기록 — 2026-11-06

## 재현과 변경

- 제공된 화면의 `위치 이동 감지 · 자동 따라잡기만 30초 대기`는 기존 `seeking()` 처리의 문구다. 마지막 확장 이동 목표와 0.5초 넘게 다른 재생 위치에서 이벤트가 오면 사용자 조작으로 분류했다. 확장 이동 이벤트가 늦게 도착하거나 치지직이 자체적으로 위치를 옮겨도 직접 되감기 없이 30초 대기가 걸리는 두 경로를 양쪽 모드의 브라우저 모형에서 재현했다.
- 일반 `seeking`/`seeked` 이벤트로 사용자 조작을 추측하는 처리를 제거했다. 본방 타임바의 실제 포인터 입력 또는 입력창 밖의 실제 되감기 키 입력이 있을 때만 선택 위치를 보호한다. 방식 스위치의 라디오 방향키는 보호를 발동하지 않는다. `지금 따라잡기`는 직접 조작 보호도 즉시 해제한다. 일시정지·사용자 배속·다시보기 제외는 유지한다.
- 안정 우선의 여유는 0.75~1.5초, 최소 지연은 0.35~0.75초로 제한한다. 반복 버퍼링에도 목표 여유를 6초까지 늘리지 않는다. 계산 함수에서도 오래되거나 과도한 여유 값을 선택 모드의 범위로 제한한다.
- 안정 우선도 준비된 영상이 있으면 시작과 미디어 이벤트에서 보정하며, 시작·광고 종료 5초 또는 버퍼링 뒤 15초 고정 대기를 없앴다. 양쪽 모두 `canplay`/`playing` 신호가 오면 짧은 회복 대기를 해제한다. 큰 지연은 다운로드된 탐색 가능 버퍼 안에서 이동하고 작은 차이는 배속으로 줄인다. 자동 이동 간격은 안정 3초·최소 지연 2초이며 미디어 이벤트에서도 강제 이동 경로로 이 제한을 우회하지 않는다. 이동 직후 중복 탐색을 피하는 0.75초 보호는 유지한다.
