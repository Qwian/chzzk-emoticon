# 0.10.16 검증 기록 — 2026-11-06

## 확인한 대기와 변경

- 기존 플레이어 코드는 시작·메타데이터 전환 뒤 5초, 버퍼링 뒤 15초, 광고 종료 뒤 5초를 기다렸다. 자동 이동은 목표보다 5초 이상 밀렸을 때만 허용하고 이동 간격은 20초로 제한했다. 버퍼 여유는 1.5초에서 시작해 안정 재생 시 최소 0.75초까지 낮췄다. 이 값들이 실제 사용자가 보는 전체 지연의 원인이라고 확정한 것은 아니다.
- 시작의 고정 대기를 없애고 `readyState`로 준비 여부를 확인한다. 최신 다운로드 버퍼의 0.35초 전을 목표로 하며, 목표보다 1초 넘게 밀리면 버퍼 안에서 이동한다. 이동 간격은 2초, 이동 후 대기는 0.75초다. 작은 차이는 1.05/1.15배속으로 보정한다.
- `progress`·`timeupdate`·`playing`·`canplay`에서 문서 탐색·광고 배치 변경 없이 가벼운 보정만 수행한다. 이벤트가 몰리면 100ms 내 중복 계산을 억제하며 별도 고빈도 타이머를 추가하지 않는다. 영상 교체 시 이전 이벤트를 해제한다.
- 실제 버퍼링에서는 여유를 0.25초씩 늘린다. `playing`/`canplay`가 오면 회복 대기를 즉시 끝내며, 신호가 없으면 2초 뒤 재검사한다. 안정 재생 10초마다 여유를 0.1초 줄인다. 광고 종료 대기는 0.75초다. 사용자의 일시정지·수동 배속·되감기 및 다시보기 보호를 유지한다.
- 자동 따라잡기 체크 상태에서 버튼 글자와 SVG가 초록색 `#00dc91`로 표시된다. 해제하면 흰색 35% 반투명으로 돌아온다. 기본 플레이어 컨트롤의 숨김 동작을 유지한다.
- Enter 전송은 기존 동기 경로이며 확장의 별도 전송 대기·메시지 큐가 없다. 전송 경로를 바꾸거나 자동 전송을 추가하지 않았다.

## 검증

- 수정 전 실제 스크립트를 새 지연 모형에 넣었을 때 15개 중 6개 실패: 시작 대기, 작은 지연 보정, 수신 이벤트 처리, 재생 가능 복귀, 수동 조작 후 이벤트 복귀, 버퍼 회복 대기. 수정 전 JSON은 `artifacts/regression-0.10.16-before.json`에 보존한다.
- 수정 후 브라우저 모형 12개 페이지의 검사 191개 통과, 페이지 예외 없음. 지연 최소화 16개, 닫힌 패널에서 초록색 글자·SVG 및 해제 복귀, 입력/IME/전송, 광고 음량·배치·배속·초기화, CHZZK/SOOP 플레이어 동작을 포함한다.
- 루트 JavaScript 전체 문법 검사 및 manifest 파싱 통과. Node 검사 30개 통과.
- 실제 unpacked v0.10.16을 격리 Edge 프로필에 로드하는 정상 초기화·초기 helper 누락 복구 2개 경로 통과. manifest 로드와 player 초기화, 광고 스킵·음소거 확인, 확장 실행 예외 없음.
- 배포 ZIP은 이전 버전과 같은 39개 리소스 목록으로 생성했다. 압축 무결성과 각 파일의 현재 프로젝트 파일 일치를 확인했다. SHA-256: `a6818709588c2b1f1b2bfde84f221f0500f059dc1a8cac79dd42aacf674caeb4`.

실제 로그인 채팅을 입력하거나 전송하지 않았다. 스트리머의 화면 속 채팅에 뜰 때까지의 시간과 사용자 웨일에서의 끊김 빈도는 측정하지 않았다. 최신 버퍼와의 0.35초 목표를 전체 방송 지연이나 실제 체감 개선 측정값으로 해석하지 않는다. 더 작은 버퍼 여유는 불안정한 회선에서 버퍼링을 늘릴 수 있으며 실제 끊김에 따라 여유를 자동으로 늘린다. 확장과 열린 치지직 탭을 모두 다시 로드해야 적용된다.
