# 0.10.8 검증 기록 — 2026-11-01

## 재현

사용자는 치지직에서 영상 클릭 후에도 스페이스가 동작하지 않고, 확장 0.10.7 재로드와 탭 새로고침 후에도 같다고 보고했다.

기존 단축키 복구 코드는 광고 컨테이너 안의 영상에 화면 크기가 있고 ended가 false이면 광고 중이라고 판단했다. 소스 없는 빈 영상과 data URL 자동재생 검사 영상에도 이 조건이 성립하므로, 네이티브 단축키가 처리되지 않을 때 보조 실행까지 건너뛴다. 공개 라이브 검사 중 소스 없음·readyState 0·양수 크기의 광고 영상을 관찰했다. 이것만으로 사용자 탭의 정확한 원인을 확정한 것은 아니다.

회귀 검사에 같은 상태를 넣으면 0.10.7의 스페이스 복구 검사 2개가 실패하며, 수정본에서는 통과한다.

## 수정

- 네이티브 `pzp-pc--adbreak` 상태로 실제 광고 준비 단계를 보호한다.
- 그 밖의 광고 영상 검사는 준비된 실제 소스와 양수 화면 크기를 함께 확인한다. 빈 영상과 data URL 검사 영상은 제외한다.
- 입력창·일반 버튼·수정키·모달 제외, 정상 네이티브 처리의 중복 방지와 F11 보호는 유지한다.

## 검증

- 치지직 단축키 모형 24개, SOOP 단축키 모형 21개 통과. 검사 페이지의 pageerror 없음.
- 실제 공개 다시보기 `https://chzzk.naver.com/video/15964028`의 본편이 재생되고 광고가 끝난 뒤, 빈 SDK 검사 영상을 추가하고 네이티브 키 처리를 차단하는 동일한 조건으로 대조했다. 별도 임시 프로필에 로드한 0.10.7 단축키 코드에서는 빈 소스와 data URL 두 조건 모두 스페이스 전후 paused가 false로 유지됐다. 수정본은 false → true, true → false로 네이티브 재생 버튼을 통해 정지·재생됐으며 pageerror 없음. 실제 사이트 플레이어를 이용했지만 실패 조건은 검사 코드로 넣은 것이며, 사용자 웨일 증상 전체를 그대로 복제한 검사는 아니다.
- 루트 JavaScript 전체 문법, manifest 파싱·참조 스크립트 존재 확인, Node 검사 29개, `git diff --check` 통과.
- 사용자 웨일 창 직접 조회는 도구의 창 소유자 검증 오류로 실패했다. 실제 로그인 채팅 입력·전송은 수행하지 않았다. 사용자 웨일에서의 최종 재발 여부는 별도 확인이 필요하다.
