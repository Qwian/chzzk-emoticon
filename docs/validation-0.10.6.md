# 0.10.6 검증 기록 — 2026-11-01

## 실제 광고와 AdGuard 규칙으로 재현

사용자 웨일에 활성화된 AdGuard 5.5.3.28의 한국어 필터에서 다음 규칙을 확인했다.

```text
chzzk.naver.com#$?#.webplayer-internal-core-shadow > .wpc-pos-abs { remove: true; }
```

이 규칙의 제거 대상에는 `.webplayer-internal-core-ad-ui`도 포함된다. 기존 확장은 문서의 광고 영역만 조회하므로, SDK가 제거된 영역에 나중에 광고 영상을 만들면 찾지 못한다. 영역을 표시하는 CSS로도 문서에서 제거된 영역을 복원할 수 없다.

공개 다시보기 `https://chzzk.naver.com/video/15964028`의 실제 광고에 이 제거 동작을 적용했다. 기존 0.10.5에서는 광고 영상이 `isConnected:false`, 화면 크기 0×0, `paused:false`, `muted:false`였고 재생 시간이 0.37초에서 13.51초까지 증가했다. 화면에서 사라진 광고가 음소거 없이 계속 재생되는 경로를 확인했다.

수정 후 같은 조건에서 실제 광고는 문서 밖에 유지된 채 `muted:true`로 처리됐다. 본편은 `muted:false`를 유지했고 광고 종료 후 재생 위치가 다시 증가했다. 해당 실제 광고의 스킵 버튼은 끝까지 SDK의 `hide` 상태였으므로 누르지 않았다. 실제 광고의 활성 스킵 성공이나 사용자 웨일에서의 해결까지 확인한 결과는 아니다.

AdGuard 전용 설정·필터를 별도 임시 Edge 프로필에 복사한 조합도 확인했다. AdGuard 5.5.3.28과 ruleset_2/227/7, 수정 확장이 함께 로드됐다. 이 조합의 공개 영상에서는 광고 요청이 차단되어 본편만 재생됐으므로, 이것만으로 소리 잔류 증상을 재현했다고 간주하지 않는다. 사용자 웨일의 로그인 상태·전체 차단 조합은 복제하지 않았고 원본 설정은 변경하지 않았다.

## 수정

- 광고 DOM 추적을 `document_start`로 옮겼다. 같은 작업 안에서 삽입·제거된 영역과 제거 후 생성된 광고 영상도 원래 연결된 플레이어에 한해 추적한다.
- 제거된 SDK 광고에도 기존 음소거·배속 처리를 적용하고 활성 기본 스킵 버튼을 처리한다. SDK의 hide·비활성·카운트다운 상태는 유지한다. 광고 DOM을 다시 붙이지 않는다.
- 문서 밖 광고의 음소거 이벤트는 해당 영상에서도 차단해 본편의 공유 음소거 상태에 전파되지 않게 한다.
- 원래 플레이어가 없어지거나 다른 페이지로 이동하면 남은 문서 밖 광고 재생을 정리한다. 빈 영상·data URL 자동재생 검사용 영상은 제외한다.

## 검증

- 새 제거 순서 회귀 검사 12개 통과. 기존 0.10.5와 비교하면 추적, 음소거/배속, 활성 기본 스킵, 이동 후 정리 4개가 실패한다.
- 기존 광고 배치 8개, 스킵 13개, 음소거/화질 6개, 소리 복원 7개, 광고 배속 19개, 사이트/플레이어 11개 통과. CHZZK·SOOP 단축키 검사도 통과했다. 검사 페이지의 pageerror 없음.
- 루트 JavaScript 전체 문법, manifest 파싱 및 참조 리소스, Node 검사 29개, `git diff --check` 통과.
- 실제 로그인 채팅 입력이나 전송, 게임 창 조작은 수행하지 않았다.

적용하려면 확장을 다시 로드한 뒤 기존 다시보기 탭도 새로고침해야 한다. 사용자 웨일에서의 최종 증상 해소는 별도 확인이 필요하다.
