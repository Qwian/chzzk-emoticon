# 0.10.18 검증 기록 — 2026-11-06

## 변경과 확인 범위

- 사용자가 방식 드롭다운을 클릭하면 실제 마우스 커서가 다른 위치로 움직인다고 보고했고, 좌우로 움직이는 스위치 형태를 요청했다. 확장 코드에서 포인터 잠금이나 OS 커서 위치 변경 호출은 발견하지 못했으며 실제 웨일의 커서 이동은 재현하지 못했다. 원인을 OS 또는 특정 설정으로 단정하지 않는다.
- 플레이어와 확장 팝업의 방식 `<select>`를 제거하고 동일한 이름의 네이티브 라디오 2개와 CSS 선택 배경으로 교체했다. 선택 배경만 0.22초에 걸쳐 좌우로 이동하며 조작 영역은 움직이지 않는다. **지금 따라잡기**와 동일한 초록색·둥근 모서리를 사용한다.
- 라디오의 기본 상호 배타 동작으로 하나만 선택하며 기존 `catchUpMode` 저장값과 화면 간 동기화를 유지한다. Tab·좌우 방향키 조작과 키보드 포커스 표시를 지원하고, 자동 따라잡기 해제 시 fieldset 전체를 비활성화한다. 애니메이션 감소 OS 설정도 존중한다.
- 두 방식의 실제 재생 정책과 기본 안정 우선은 변경하지 않았다. 포인터 위치·OS 마우스 설정을 수정하는 처리는 추가하지 않았다.

## 검증

- 격리 Edge의 Playwright 포인터/키보드 입력으로 플레이어와 팝업 양쪽을 검사했다. 네이티브 방식 드롭다운 부재, 단일 선택, 애니메이션 중간·종료 위치, 조작 영역의 고정, 반복 클릭 뒤 최종 저장값, 좌우 방향키 전환, 포인터 잠금 없음과 추가 페이지 없음, 페이지 예외 없음을 확인했다. 화면 PNG도 확인했다. 증거: `artifacts/catch-switch-0.10.18.json` 및 같은 이름의 player/popup PNG.
- 모형 5개 페이지 검사 84개 통과: 설정 저장·동기화·켜짐 초록색·비활성화, 안정/최소 지연 실행 정책, 버퍼링 회복과 수동 조작 보호, 광고 처리 기본 회귀. 페이지 예외 없음.
- 루트 JavaScript 문법 검사와 manifest 파싱, Node 검사 32개 통과.
- 실제 unpacked v0.10.18을 격리 Edge 프로필에 로드하는 정상 초기화·초기 helper 누락 복구 2개 경로에서 초기화·광고 음소거/스킵과 실제 확장 팝업의 최소 지연 스위치 저장을 확인했다. manifest 및 확장 실행 예외 없음.
- 배포 ZIP 39개 리소스의 압축 무결성과 프로젝트 파일의 바이트 일치를 확인했다. SHA-256: `2b5f5f9998000c6b13d014490caa90283f27f531b4deda94ca174a25d9ecfc9f`.

OS 커서가 실제로 튀는지 여부와 사용자 웨일에서의 동작은 모형 검사로 확인할 수 없다. 이번 변경은 기본 드롭다운 팝업을 제거한 것이며 사용자 보고 증상의 해결 확인은 별도로 필요하다. 로그인한 실제 채팅에 입력하거나 전송하지 않았다.
