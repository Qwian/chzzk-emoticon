# 0.10.17 검증 기록 — 2026-11-06

## 변경

- 사용자가 0.10.16의 적극적 따라잡기를 적용한 뒤 간헐적인 끊김을 보고했다. 작은 버퍼 여유는 끊김을 늘릴 수 있으나 사용자 방송에서 원인을 직접 측정한 것은 아니다. 기존의 안정적인 방식도 선택할 수 있도록 요청한 범위를 구현했다.
- `features.catchUpMode`는 `stable` 또는 `lowLatency` 하나만 저장하는 단일 선택이다. 누락·잘못된 값은 `stable`로 정규화한다. 기존의 `catchUp: false`는 유지한다. 플레이어 패널과 확장 팝업에 같은 두 옵션을 추가했으며 저장소 변경으로 동기화한다. 두 컨트롤러를 병렬 실행하지 않는다.
- **안정 우선 (이전 방식)**이 기본이다. 0.10.15의 버퍼 여유(초기 1.5초/최소 0.75초), 시작·소스 전환 5초, 버퍼링 회복 15초, 광고 종료 5초, 이동 후 4초 대기, 이동 간격 20초, 1.03/1.08배속과 안정 재생 60초마다 여유 감소를 복원했다. 이 방식은 미디어 이벤트로 보정을 실행하거나 회복 대기를 해제하지 않는다.
- **최소 지연 (끊길 수 있음)**은 0.10.16의 0.35초 목표, 이벤트 보정, 짧은 회복 및 1.05/1.15배속을 유지한다.
- 실행 중 방식 변경 시 확장 소유 배속을 복원하고 버퍼 여유·회복·이동 상태를 새 방식으로 초기화한다. 수동 배속·되감기 보호 및 켜짐의 초록색 표시를 유지한다. 자동 따라잡기 해제 시 방식 선택도 비활성화한다.

## 검증

- 기존 커밋 `74defde`의 안정 방식 및 `09b3833`의 최소 지연 방식과 새 계산 결과를 각 5,000개 입력으로 대조했다. 강제/자동 이동, 버퍼 구멍·부족, 여유와 시간 경계를 포함한 총 10,000개 결과가 일치했다. 증거: `artifacts/catch-up-policy-0.10.17.json`.
- 브라우저 모형 10개 페이지, 검사 142개 통과 및 페이지 예외 없음. 안정 방식의 시작 대기·작은 지연 보정·버퍼링 뒤 15초 회복과 20초 이동 보호, 안정↔최소 지연 즉시 전환, 끄기/다시 켜기, 두 화면의 단일 선택·동기화·초록색 표시, 기존 광고 배치·음량·배속·초기화 회귀를 검사했다.
- 루트 JavaScript 문법 검사, manifest 파싱, Node 검사 32개 통과.
- 실제 unpacked v0.10.17을 격리 Edge에 로드한 정상 초기화·초기 helper 누락 복구 2개 경로 통과. manifest/player 초기화와 광고 음소거·스킵을 확인했으며 확장 실행 예외 없음.
