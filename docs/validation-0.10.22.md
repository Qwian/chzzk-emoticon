# 0.10.22 검증 기록 — 2026-11-06

## 재현한 원인

- 사용자 화면은 자동 따라잡기 체크와 `수동 배속 사용 중 · 자동 따라잡기 대기`가 동시에 표시됐다. `media-speed.js`는 배경 스크립트에서 받은 배속을 모든 대상 영상에 적용하며 1배속에도 `chzzkToolsManualRate`를 붙였다. `player-tools.js`는 그 표시가 있으면 종료했고, 표시가 없어도 기존 배속이 1이 아니면 종료했다.
- 기존 모형 대부분은 두 스크립트를 함께 실행하지 않았으며 낮은 지연 모형도 수동 표시가 자동 보정을 중단하는 동작을 성공 조건으로 검사했다. 이번에는 실제 전역 배속·플레이어·채널 UI 스크립트를 함께 실행해 체크와 실제 재생 속도를 동시에 확인한다.
- 캐시 배속 1/1.5/2와 두 실행 순서의 6개 조합 모두에서 체크는 참이지만 실제 배속은 캐시 값으로 고정되고 사용자 화면과 같은 문구가 나오는 것을 재현했다. 전후 증거: `artifacts/catch-up-rate-0.10.22-before.json`, `artifacts/catch-up-rate-0.10.22-after.json`.

## 변경

- 체크가 켜진 라이브 본방에 자동 배속 소유권을 표시하고, 수동 표시와 비정상 배속을 이유로 자동 보정을 종료하던 두 조건을 제거했다. 네이티브 배속 변경도 미디어 이벤트에서 다시 검사한다.
- 전역 배속 기능은 자동 보정이 소유한 본방의 수동 표시를 지우고 해당 영상에 저장된 배속을 강제 적용하지 않는다. 해당 영상의 배속 키는 자동 조절 중임을 안내하며 자동 보정을 중단하거나 배경에 새 수동 명령을 보내지 않는다. 다른 영상·오디오는 수동 조절을 유지한다.
- 끄기·영상 교체·라이브/다시보기 전환·페이지 종료에는 소유권을 해제하고 기존 수동 배속 적용을 재개한다. 켜기·라이브 복귀 때는 자동 조절이 다시 우선한다. 새 타이머나 자동 위치 이동을 추가하지 않았다.
- 페이지 버전 응답에 남은 0.10.14 고정값을 현재 0.10.22로 맞췄다.

## 검증
