# 0.5.1 검증 기록 — 2026-10-29

## 변경

- CHZZK 문서 시작 시 확인된 라이브·다시보기 메타데이터의 `dab: true`를 보정한다. 원래 화질 메뉴에서 최고 화질을 선택하는 기존 기능과 함께 사용한다.
- 광고 전용 영역의 표시된 활성 Skip 버튼을 250ms 간격으로 확인한다. SDK의 `hide`, 숨김 부모, 비활성·카운트다운·종료 상태는 제외한다. 클릭이 반영되지 않으면 같은 버튼·영상에서 1초 간격으로 최대 세 번만 시도한다.
- 두 기능 모두 기본 켜짐이며 팝업에서 끌 수 있다. 감지값 보정 설정은 새로고침 후 초기 메타데이터부터 적용된다.

## 근거와 확인 범위

사용자가 AdGuard를 치지직에서 잠시 끄고 새로고침하자 720p·1080p 메뉴가 복구됐다고 확인했다. 이것은 사용자 환경에서의 충돌 근거이며, 이번 수정의 실제 고화질 복구를 검증한 결과는 아니다.

현재 치지직의 [공개 페이지 코드](https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/index-DWn2Eab5.js)에서 `forceLowResolution: !!m.dab` 전달과, 해당 값이 참이면 360p 트랙을 선택하는 처리를 확인했다. [공식 플레이어 코드](https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/player-vendor-BHKPSRAP.js)에서 광고 버튼의 `data-role="skipBtn"`, `aria-label="광고 SKIP"`, 초기 `hide` 클래스와 `SKIPPABLE` 상태에서만 실행되는 클릭 핸들러를 확인했다.

페이지 시작 시 JSON 해석 처리를 연결한다. 저장된 설정을 읽기 전에는 응답을 변경하지 않는다. 확인된 채널 ID·방송 ID·제목이 있는 메타데이터만 보정하며, 사용자 reviver를 사용하는 JSON, 오류 응답과 알 수 없는 구조는 그대로 통과한다. API의 Response.json 경로도 처리한다. 영상 주소·P2P·접근 제한·광고 일정은 수정하지 않는다.

## 통과한 검사

- 루트 JavaScript 전체와 포함된 HLS 코드의 Node 문법 검사, manifest JSON 파싱, `git diff --check`.
- Node 8개 테스트: 영타 변환·따라잡기 기존 4개 및 메타데이터 보정 4개. 시작 순서·설정 꺼짐·다시보기·잘못된 구조·오류 응답·일반 JSON·reviver·API URL 범위를 가상 응답으로 검사했다.
- 브라우저 로컬 harness 14개 묶음, 76개 항목. 기존 63개와 광고 Skip 13개 모두 통과했다. 실제 확장 파일을 로컬 페이지에서 실행하며 저장소와 광고 버튼 상태는 테스트용으로 모사했다.
- 실제 치지직 채팅에 입력하거나 전송하지 않았다.

## 남은 실제 환경 확인

현재 도구에서는 브라우저 확장 관리 페이지가 차단되어 등록된 개발 확장을 다시 로드할 수 없다. 기존 프로젝트 폴더의 코드 변경은 끝났으나, 사용자 브라우저에서는 확장 다시 로드 후 방송 탭 새로고침이 필요하다.

AdGuard를 켠 사용자 브라우저에서 720p·1080p 메뉴와 실제 영상 해상도가 유지되는지, 실제 광고 Skip이 눌리는지는 아직 확인하지 못했다. 서버가 낮은 화질 스트림만 제공하거나 다른 필터가 영상 요청을 차단하는 경우까지 해결됐다고 주장하지 않는다.
