# 0.5.2 검증 기록 — 2026-10-29

## 재현과 수정

사용자가 제공한 오류는 `media-speed.js:89`의 `chrome.runtime.sendMessage()`에서 발생한 `Uncaught Error: Extension context invalidated.`다. 기존 코드는 반환된 Promise의 거부만 처리하므로, API 호출 자체가 동기 예외를 던지면 주기 타이머에서 전역 오류가 반복된다.

0.5.1 코드를 별도 로컬 fixture에서 실행하고 해당 API가 같은 동기 예외를 던지게 하자, 같은 전역 오류가 반복됐고 키 가로채기와 배속 고정도 남았다. 실제 브라우저에서 사용자가 확장을 다시 로드한 과정을 직접 관찰한 것은 아니며, 오류 경로를 모사한 재현이다.

0.5.2는 확장 ID 유효 여부를 확인하고, API 호출과 Promise 거부를 모두 처리한다. 컨텍스트가 사라지면 배속 제어의 주기 타이머·DOM 관찰·키/미디어/확장 이벤트·영상 프레임 수집을 정리한다. 뒤늦게 도착한 응답이 이전 배속 제어를 되살리지 않게 한다. 현재 재생 속도를 강제로 바꾸거나 페이지를 자동 새로고침하지 않는다. 연결이 유효한 일반 통신 오류는 영구 종료로 처리하지 않는다.

## 통과한 검사

- 루트 JavaScript 문법 검사, manifest JSON 파싱, `git diff --check`.
- 기존 Node 8개 테스트.
- 로컬 브라우저 연결 수명 검사 5개 시나리오, 31개 항목: 주기 통신의 동기 예외, 키 입력의 동기 예외, 비동기 거부, 확장 ID 소실, 일시 통신 실패 후 재사용.
- 기존 배속·프레임 이동·입력창 제외·iframe 명령 전달 9개 항목.
- 실제 치지직 채팅에는 입력하거나 전송하지 않았다.

## 적용 범위

코드와 등록된 프로젝트 폴더는 갱신했지만, 브라우저 확장 관리 화면의 도구 접근 제한으로 사용자의 확장을 직접 다시 로드하지 못했다. 이미 실행 중인 0.5.1 코드에는 이 수정이 소급 적용되지 않는다. 등록된 확장 다시 로드 후 방송 탭을 새로고침해야 한다. 실제 확장 다시 로드와 탭 새로고침 조합에서의 확인은 사용자 브라우저에 남아 있다.
