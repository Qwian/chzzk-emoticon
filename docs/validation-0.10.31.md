# 0.10.31 검증 기록 — 2026-11-17

## 웨일에서 재현한 원인

사용자는 0.10.30 이후에도 Alt+휠이 전혀 작동하지 않는다고 보고했다. 앞선 Edge 및 공개 페이지 검사는 웨일의 입력 경로를 검증하지 못했다. 설치된 웨일 5.41.429.5의 버전 디렉터리 실행 파일로 격리 프로필을 실행해 비교했다. 루트 실행 래퍼는 Playwright 연결이 종료되어 버전 디렉터리의 실제 실행 파일을 사용했다. 사용자 프로필을 복사하거나 설정을 편집하지 않았다.

같은 키·휠 입력에서 실제 페이지에 도착한 값:

```text
keydown: code=AltLeft, altKey=true
wheel:   deltaY=-120, altKey=false
keyup:   code=AltLeft, altKey=false
```

0.10.30(`58c49f4`)은 휠의 `altKey`가 false라는 이유로 종료하여 영상 배율이 100% 그대로였다. 실제 Alt 누름·뗌 상태를 사용하는 수정 후 같은 웨일 입력으로 110%가 됐다. 원시 이벤트는 `artifacts/whale-wheel-baseline.json`, 최종 회귀 기록은 `artifacts/media-zoom-0.10.31.json`에 보존했다. 이는 동일 설치 엔진의 격리 프로필에서 DevTools 입력 주입으로 재현한 결과이며 사용자 로그인 프로필의 물리 휠을 직접 관측한 것은 아니다.

## 변경

- 키보드의 Alt/Ctrl/Meta 눌림 상태를 추적하고, 휠에서 Alt 표시가 빠지면 그 상태를 함께 사용한다. 키 해제·창 포커스 이탈·기능 해제·확장 무효화에서 상태를 지운다. 신뢰할 수 있는 마우스 재진입·버튼 입력의 보조키 상태로도 갱신한다.
- 상위 페이지에 키보드 포커스를 둔 채 cross-origin iframe 위에서 휠을 돌리면 iframe에는 키 누름이 들어오지 않는 문제도 재현했다. 같은 탭 안의 프레임 사이에서 보조키 불리언 상태만 공유해 이 경우도 110%가 되는 것을 확인했다. 다른 탭으로 공유하지 않으며 이전 상태가 새 키 해제를 덮지 않게 순서를 확인한다. 키 입력 문자열·채팅 내용은 기록하지 않는다.
- 웨일 기본 마우스 설정 변경 없이 처리하며 확장 권한도 추가하지 않았다. 기존 하단 메뉴·드래그·영상 전용 확대를 유지한다.
- 브라우저 검사기에 `--whale`을 추가했다. 설치 버전의 실제 실행 파일을 선택하고 `WHALE_EXECUTABLE`로 경로를 지정할 수도 있다. 휠 변경은 Edge 통과만으로 완료하지 않도록 프로젝트 검사 지침을 보완했다.

## 검증

- JavaScript 문법·manifest 0.10.31 파싱·`git diff --check` 통과. Node 검사 50개 통과.
- 설치 웨일에서 실제 unpacked 0.10.31 로드 및 원시 이벤트의 `keydown.altKey=true / wheel.altKey=false`를 기록했다. 브라우저 모형 225개 검사 통과(확대 33개, 기존 하단 메뉴·채팅 192개), 실패·페이지 실행 예외 없음.
- 실제 브라우저 키·마우스 입력으로 세로 휠 110%, 가로 휠 120%, 영상 밖 휠 130%, 포커스 상태를 지운 뒤 Alt를 누른 채 마우스 재진입 후 140%를 확인했다. 키 해제 뒤 일반 휠은 확대하지 않으며 Ctrl 조합 제외와 blur 초기화도 검사했다.
- 상위 페이지에 키보드 포커스를 두고 cross-origin iframe에서 Alt+휠로 110% 확대, Alt 해제 후 일반 휠은 110% 유지했다. 실제 서비스 워커 IPC를 사용했다. 팝업 페이지 검사의 소유 탭 조회만 모사한 조건은 이전 버전과 같다.
- 플레이어/영상 단독 전체화면의 방향 버튼·드래그·슬라이더와 재생 유지, 자유 배치 채팅 회귀를 통과했다.
- 같은 웨일에서 로그아웃한 공개 다시보기 `https://chzzk.naver.com/video/15964028`의 광고 종료와 본편 실제 재생을 기다렸다. 키 입력 후 영상 폭 687 → 858.75px(125%)와 이동·초기화, 영상 안 세로 휠과 영상 밖 가로 휠의 110%/120% 확대를 확인했다. 하단 조절판 사용 중 메뉴 유지와 마우스 이탈 시 숨김도 통과했다.

실행: 번들 Node `--test tests/*.test.cjs`, `tests/media-zoom.browser.cjs --whale --public`. 사용자 웨일 창의 네이티브 자동화는 창 소유자 확인 오류로 조회되지 않았다. 사용자 로그인 탭은 직접 조작하지 않았으며 적용에는 확장 재로드와 방송 탭 새로고침이 필요하다.
