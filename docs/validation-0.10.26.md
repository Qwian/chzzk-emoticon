# 0.10.26 검증 기록 — 2026-11-07

두 치지직 방송을 동시에 시청할 때 렉이 심하다는 제보에 따라 따라잡기의 과부하 회복 동작을 보강했다. 사용자 웨일의 실제 재생 상태나 PC 자원 사용량을 측정하지 않았으므로 이번 제보의 단일 원인을 확정하지 않는다.

## 재현과 변경

- 실제 `player-tools.js`를 두 독립 미디어 시계/디코더 카운터로 실행했다. 수정 전에는 프레임 누락 25%에서도 두 영상 모두 1.15배속을 유지했고, 반복 waiting/canplay가 가속을 즉시 재개했다.
- 별도 Edge 두 탭에서도 동일 모형을 실행했다. 5초 안의 배속 충돌 30회에 대한 확장의 재가속 쓰기가 수정 전 30회에서 수정 후 2회로 줄었다. 브라우저는 동일한 playbackRate 대입에도 ratechange를 발생시킬 수 있어, 이벤트 수와 확장의 실제 가속 대입 수를 분리해 계측했다.
- 가속 중 1초 이상 구간에서 전체 프레임 10개 이상, 누락 3개 이상, 누락률 10% 이상이거나 재생 진행이 2초 이상 크게 지연되면 확장 소유 가속을 해제한다. 15초 안에 버퍼링 2회 또는 5초 안에 배속 충돌 3회도 보호 대상으로 한다.
- 회복은 30초부터 시작하며 반복 실패 시 60초·최대 120초로 늘린다. canplay는 이 시간을 해제하지 않는다. 영상별 상태이므로 정상인 다른 방송은 계속 따라잡는다. 카운터 초기화·일시정지·긴 백그라운드 타이머 간격은 과부하로 오인하지 않는다. 영상/소스 또는 사용자의 따라잡기 설정 변경은 상태를 초기화한다.
- 자동 currentTime 이동은 추가하지 않았다. 명시적인 지금 따라잡기는 회복 중에도 사용할 수 있으며, 회복 시간 동안 확장 가속을 재개하지 않는다.
- catch-up 소유 속성은 값이 바뀔 때만 쓴다. 건강한 재생의 폴링 10회에서 불필요한 속성 변경 20회가 0회로 줄었다. 별도 폴링이나 프레임 콜백은 추가하지 않았다.

## 검증

- 루트 JavaScript 23개 문법 검사 및 manifest v0.10.26 파싱 통과.
- Node 검사 45개 통과. 신규 9개는 두 영상 동시 과부하, 정상 영상 독립성, 배속 충돌, 반복 버퍼링, 재생 정체와 일시정지 구분, 소유 속성 쓰기, 수동 따라잡기, 회복 시간 증가, 카운터 초기화와 선택 API 미지원을 포함한다.
- 두 탭 Edge 모형: 2초·1.5초·1초의 24개 검사 통과, 페이지 예외 없음. 전후 결과: `artifacts/catch-up-health-0.10.26-before.json`, `artifacts/catch-up-health-0.10.26-after.json`.
- 기존 배속 통합 60개 및 명시적 이동/키 입력 30개 검사 통과. 전역 배속과의 소유권 충돌 방지 및 수동 버튼에서만 currentTime을 쓰는 조건을 유지했다.
- 기존 따라잡기·사이트 플레이어·광고·팝업 모형 9개 페이지의 95개 검사 통과, 페이지 예외 없음. 반복 버퍼링 관련 기대값은 새 회복 보호 동작으로 변경했고 단발 버퍼링의 빠른 회복은 유지했다.
- 실제 unpacked v0.10.26을 격리 Edge에 로드했다. 정상 초기화와 초기 광고 도우미 누락 폴백 모두 서비스 워커 버전·팝업 설정 저장·광고 초기화를 통과했고 실행 예외 없음.
- 배포 ZIP의 33개 리소스에 대해 CRC 무결성, manifest 참조 누락 없음 및 현재 소스와 바이트 일치를 확인했다. SHA-256: `02e41826449ac701ed0f98de566168c88247f6aac0778037844917ecd494b410`.

위 검사는 제어된 모형이며 실제 동시 라이브의 FPS 개선을 입증하지 않는다. 실제 로그인 채팅 입력·전송은 하지 않았다. 사용 중인 확장과 열린 치지직 방송 탭 두 개를 모두 다시 로드한 뒤 사용자 환경에서 확인해야 한다.
