# 0.10.13 검증 기록 — 2026-11-01

## 원인 경로와 변경

- 기존 광고 음소거는 1초 간격의 플레이어 검사와 readyState >= 2 판정을 기다렸다. SDK 소스 로딩 후 첫 재생까지 사이에 음소거되지 않은 구간이 생기는 것을 모형으로 재현했다. 특정 과거 커밋 하나를 사용자 증상의 시작점으로 단정하지 않는다.
- 광고 플레이어 도구를 document_start에도 실행해 준비한다. document_idle의 중복 실행 방지와 초기 helper 누락 시 복구 경로는 유지한다.
- 광고 소스·컨테이너 변화, 로딩·재생·음량 이벤트에서 즉시 갱신한다. 광고 컨테이너가 문서에서 제거된 뒤에도 같은 관찰을 유지한다. 속성을 관찰하는 범위는 광고 컨테이너와 플레이어의 광고 상태 클래스로 제한한다.
- 실제 SDK 소스가 로딩 중이면 adbreak 표시 전에도 음소거하되, 빈 자동재생 probe는 제외하고 실제 재생 가능한 광고 판정과 구분한다. 본편 음소거 이벤트는 차단하지 않는다.
- 광고 음소거 해제 설정, 종료 시 원래 값 복원, 본편 소리 복원, 기본 스킵과 배속 동작은 유지한다. 본편을 강제로 재생하거나 탐색하지 않는다.

## 검증

- 시작 시점 모형 19개 포함 광고·배속·본편 소리·스킵·초기화·제거된 DOM·사이트 도구 모형 103개 통과. 페이지 오류 없음.
- 실제 확장 로드 모형 2개 통과: 정상 document_start 초기화, 초기 광고 helper가 빠졌을 때 document_idle 복구. manifest 오류·확장 예외 없음.
- 실제 공개 치지직 다시보기 광고에서 loadstart(readyState=0), loadedmetadata, loadeddata, play, playing 모두 muted=true 확인. 10ms 간격 관찰과 이벤트를 합친 재생 중 표본 1,380개 중 muted=false는 0개였다. 광고 뒤 본편 paused=false, muted=false, 재생 위치 진행을 확인했다. 페이지 오류 없음.
- 확장 없는 별도 브라우저의 같은 공개 다시보기에서도 광고 재생 중 본편 paused=true와 재생 위치 정지를 확인했다. 사용자가 설명한 '광고 중에만 멈춤'은 사이트 기본 동작으로 판단한다.
- 루트 JavaScript 전체 문법, manifest 파싱, Node 검사 29개 통과.
- 음소거 상태와 재생 상태를 확인한 결과이며 실제 스피커 출력 녹음은 수행하지 않았다. 사용자 웨일·AdGuard 조합에서의 최종 청취 확인과 실제 로그인 채팅 입력·전송은 수행하지 않았다. 게임 조작 없음.

원시 결과 JSON, 확장 테스트 프로필, 배포 ZIP은 Git에서 제외한 `artifacts/`에 보존한다.
